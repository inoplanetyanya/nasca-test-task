# Simple DevOps API App

Тестовое задание для DevOps Junior. Проект содержит REST API приложение на FastAPI с жесткой валидацией данных, упакованное в Docker-контейнер с использованием Multi-stage сборки. Локальное окружение разворачивается через Docker Compose, процесс тестирования и линтинга полностью автоматизирован через GitHub Actions CI и Makefile, а деплой на целевые сервера описан с помощью Ansible-ролей.

Все ключевые параметры инфраструктуры (порты хоста и контейнера, имена, теги, пути деплоя) изолированы в едином файле конфигурации `.env` (реализация принципа Single Source of Truth).

## 🚀 Быстрый старт через Makefile

Проект полностью автоматизирован для работы в Linux-окружении или Git Bash. Для просмотра всех доступных команд выполните:
```bash
make help
```

### 1. Локальное развертывание (Docker Compose)
Чтобы запустить изолированное локальное окружение с автоматической проверкой здоровья, достаточно одной команды:
```bash
make compose-up
```
- **Приложение доступно по адресу**: `http://localhost:5000` (или по `HOST_PORT` из `.env`)
- **Интерактивная документация (Swagger UI)**: `http://localhost:5000/docs`
- **Просмотр логов в реальном времени**: `make compose-logs`

Для остановки окружения и полной очистки ресурсов хоста выполните:
```bash
make compose-down
```

### 2. Локальное тестирование и линтинг
Перед отправкой изменений в репозиторий качество кода и работоспособность проверяются командами:
```bash
make lint  # Запуск ruff для Python и shellcheck в Docker для Bash
make test  # Запуск автоматических тестов (pytest)
```

## 🛠 Архитектура проекта и технические решения

### 1. Изоляция конфигурации (`.env`)
В проекте реализованы принципы методологии **Twelve-Factor App**. Вся конфигурация вынесена в файл `.env`. В `Makefile` настроен автоматический импорт этих переменных (`include .env`), что делает команды динамическими. 
Порты хоста (`HOST_PORT`) и контейнера (`CONTAINER_PORT`) **разделены**: это гарантирует, что если на целевом сервере порт 5000 будет занят, инфраструктуру можно перестроить на другой внешний порт, изменив всего одну цифру в файле конфигурации, без пересборки самого Docker-образа.

### 2. REST API приложение (`/app`)
- Написано на **Python 3.12+** с использованием фреймворка **FastAPI**.
- **Валидация данных**: Входящие данные POST-запросов жестко валидируются через схемы **Pydantic v2** (проверка обязательных полей, ограничение длины строк, регулярные выражения `pattern` для защиты от спецсимволов и цифр в именах).
- Хранилище: In-Memory БД (список словарей в оперативной памяти).
- Код полностью покрыт интеграционными автотестами (`pytest` + `TestClient`).

### 3. Скрипт диагностики сервера (`/scripts/server-info.sh`)
- Самостоятельный Bash-скрипт, собирающий системные метрики хоста (hostname, ОС, kernel, uptime, CPU cores, load average, RAM, Disk).
- Принимает аргументами список URL-адресов и динамически проверяет их доступность по HTTP, замеряя точное время ответа в миллисекундах.
- Предназначен для внешней диагностики инфраструктуры хоста, написан в строгом режиме `set -euo pipefail` и на 100% проходит проверку утилитой `shellcheck`.
- Логирует сессии во временную директорию `/tmp/server-info.log`.

### 4. Контейнеризация (`Dockerfile`)
- Применена **Multi-stage (многоэтапная) сборка** на базе `python:3.12-slim`. Инструменты компиляции (`build-essential`) остаются на первом этапе, благодаря чему финальный образ весит минимум и защищен от лишних уязвимостей.
- Проект запускается под безопасным **non-root** пользователем (`appuser` с UID 10001).
- Продакшен-сервер: **Gunicorn** с асинхронными воркерами **Uvicorn**.
- В контейнер встроен нативный и легковесный **`HEALTHCHECK` через утилиту `curl`**, опрашивающий внутренний порт приложения. Это гарантирует надежность оркестрации и отсутствие лишних системных утилит хоста в рантайме контейнера.

### 5. Автоматизация развертывания (`/ansible`)
Конфигурация Ansible разделена на две переиспользуемые роли:
- **`roles/docker`** — подготавливает чистый сервер: обновляет кэш apt, подключает официальные репозитории, устанавливает Docker CE, плагин Docker Compose и активирует демон Docker.
- **`roles/app`** — создает структуру каталогов `/opt/simple-app`, синхронизирует файлы проекта (игнорируя мусорные файлы кэша), запускает стек через `docker compose` и с помощью модуля `uri` проверяет доступность эндпоинта по реальному IP-адресу целевого хоста (`ansible_host`).

Команды проверки (запускаются в изолированном контейнере, не требуя установки Ansible на хост):
```bash
make ansible-check  # Проверка синтаксиса плейбука и ролей с передачей extra-vars
make ansible-dry    # Режим имитации деплоя (--check)
```

### 6. CI Пайплайн (`.github/workflows/build.yml`)
Автоматический пайплайн GitHub Actions настроен на триггеры `push` и `pull_request` в ветку `main`. 
Пайплайн в изолированном окружении Ubuntu выполняет линтинг кода (`ruff` и `shellcheck`), прогоняет тесты Python, собирает Docker-образ и поднимает контейнер через Docker Compose с флагом `--env-file .env`. Пайплайн динамически ожидает статус `healthy` от контейнера и, в случае сбоя, автоматически дампит логи Gunicorn и `docker inspect` для быстрой отладки в веб-интерфейсе GitHub.
